# WR008: the destination is not running, is restarting, or is unhealthy

- **Layer:** 1, destination
- **Confidence:** high when the container is stopped, restarting or paused; medium when it runs but is unhealthy or crash-looping
- **Supersedes:** WR001, WR005, WR016
- **Since:** v0.1 (M1)

## The pitfall

Whatever the network looks like, nothing can connect to a container that isn't running. A container that exited, crashed or is caught in a restart loop has **no network address**: Docker releases it when the container stops. Its name then fails to resolve and its old address times out, which looks like a naming or a path problem.

whyreach checks container state **before any probe**: a restarting container can't even be joined by a probe container (`cannot join network namespace of a non running container`).

## The evidence

| Evidence | What it shows |
|---|---|
| `docker.container` of the destination | `State` (`exited`, `restarting`, `paused`, `created`, `dead`), `ExitCode`, `RestartCount`, health status, and `StartedAt` compared with when it was inspected |

| State | Confidence |
|---|---|
| exited, created, dead, removing | high |
| restarting | high |
| paused | high |
| running, but the healthcheck reports `unhealthy` | medium |
| running, but restarted at least 3 times and started less than 30 s before the inspect (a crash loop caught between restarts) | medium |

## The fix

- **Stopped:** start it (`docker compose up -d <service>`) and find out why it stopped: `docker logs <container>`.
- **Restarting:** read its logs and fix what makes it exit; a restart policy only hides the crash.
- **Paused:** `docker unpause <container>`.
- **Unhealthy:** check the healthcheck and the logs. The app may still be starting (see WR010 from M2), or failing.

## False positives and limits

- If the name matches several containers (replicas) and at least one is running and healthy, WR008 does not fire: Docker's DNS sends traffic to the running ones.
- If the name matches no container at all, that is WR005, not WR008.
- "Unhealthy" is a weaker signal than "not running": the app may accept connections and still fail its healthcheck, so it is medium confidence.
- The source container's own state is not WR008's concern: if the source isn't running, whyreach reports that it can't probe from it.
