# WR011: host.docker.internal doesn't exist on Docker Engine without a mapping

- **Layer:** 2, addressing
- **Confidence:** high when the lookup from the container fails too; medium from metadata alone (Probe? partly)
- **Supersedes:** WR005, WR016
- **Since:** v0.1 (M2)

## The pitfall

Docker Desktop gives every container the name `host.docker.internal`. Docker Engine on Linux does not: a container has it only with an explicit mapping to the special address `host-gateway`. Code and Compose files written on a Mac then fail on a Linux machine or in CI:

```
getaddrinfo ENOTFOUND host.docker.internal
Could not resolve host: host.docker.internal
```

## The evidence

| Evidence | What it shows |
|---|---|
| `docker.version` | the daemon is Linux Docker Engine, not Docker Desktop |
| `docker.container` of the source | no `extra_hosts` entry for `host.docker.internal` |
| `probe.dns` from the source (optional) | the lookup failed: confirms it |
| `host.addrs` | the docker0 address the mapping will point at, for the fix |

## The fix

```yaml
services:
  worker:
    extra_hosts: ["host.docker.internal:host-gateway"]
```

(`docker run --add-host=host.docker.internal:host-gateway`), then recreate the container. The name then points at the host's docker0 address (`172.17.0.1` by default), so the host service must listen there or on `0.0.0.0`: otherwise WR012 follows.

## False positives and limits

- It never fires on Docker Desktop, where the name works out of the box.
- If the name resolves anyway (a custom DNS server answers it), it doesn't fire.
- A container with `network_mode: host` shares the host's network namespace: it should use `localhost`.
